# 1. Monocs とは

## 1.1 ひとことで

Monocs は、Raspberry Pi Zero 2 W で動く、C で書いたシンプルなベアメタル OS です。電源を入れるとすぐシェルが出て、その場で C を書き、
コンパイルして動かせます。

名前は Mono + Computing System から来ています。同時に動くプログラムは 1 つ、アドレス空間も特権も 1 つの、
シンプルな作りだからです。文書では「Monocs」、プログラムの名前（API）では `monocs_*` と書きます。

## 1.2 大事にしていること

| 方針 | 意味 |
|---|---|
| **速さが命** | 起動、コンパイル、アプリの起動、計算の速さをいちばん大事にします。機能を足すときも速さを落とさないようにします |
| **サブ OS** | 単体で使うより、PC や Raspberry Pi 5 から USB・Wi-Fi でつないで使うのが前提です（シリアル、telnet、SSH、HTTP）。HDMI の画面とキーボードは最後に回しています |
| **Linux に合わせる** | C ライブラリ、端末、シェル、コマンドの出力は、できるだけ Linux（GNU・POSIX）と同じにしています。Linux 用に書かれたプログラムがソースのまま動き、Linux を知っている人がそのまま使えるように |
| **Monocs の中で完結** | 内蔵のコンパイラ（slimcc-a64。slimcc をもとに AArch64 向けに作り直したもの）と自作のリンカ（slimld）で、C ライブラリも OS 自身も Monocs の上で作り直せます（セルフホスト）。標準のカーネルもこのコンパイラで作っています |
| **ソースのまま動かす** | プログラムは C のソースのまま置き、動かすときにコンパイルします。2 回目からはコンパイルの結果のキャッシュを使うので速く動きます |

## 1.3 Linux と違うところ（設計そのもの）

ここは Linux に合わせていません。Monocs の設計そのものだからです。

- **同時に動くアプリは 1 つだけ**（シングルタスク）。プロセスも、`fork`・`exec` も、`&`（裏で動かす）もありません。
  ただし `system()` でほかのプログラムを呼んで、終わるのを待つことはできます（入れ子に動きます）。
- **OS もアプリも同じ特権（EL1）・同じアドレス空間**で動きます。アプリはハードウェアも OS のメモリも直接触れます。
  よくある事故（NULL の参照、OS のコードへの書き込み、スタックのあふれ）は例外で捕まえて、アプリだけを止めてシェルに戻ります。
- **仮想メモリはありません**。MMU は使いますが、番地と物理番地が同じ（恒等マップ）で、プロセスごとの番地の空間もスワップもありません。
  MMU は、キャッシュを効かせることと、上の事故を捕まえるページの守りに使っています。守るのはバグからだけで、悪意のあるプログラムからは守れません（[第 12 章](12-internals.md) の 12.5）。
- **システムコールはありません**。アプリは OS の関数（`printf`・`open`・`read` なども）を、ふつうの関数として直接呼びます。
  呼ぶ手間はふつうの関数呼び出しと同じです（[第 12 章](12-internals.md) の 12.6）。
- **マルチコアは「アプリがコアを借りる」形**です。4 つのコアのうち、コア 3 は裏で動くサービス用で、アプリはコア 0〜2 の 3 つを
  使えます。pthread はスレッド 1 つにコアを 1 つまるごと渡します（スケジューラはありません）。
- **ファイルシステムは SD カードの FAT32** だけです。パーミッションと所有者はなく、大文字と小文字を区別しません。
- **時計（RTC）がない**ので、時刻はネットワーク（NTP）から合わせます。

## 1.4 ハードウェア

| 項目 | 内容 |
|---|---|
| 基板 | Raspberry Pi Zero 2 W（SoC は RP3A0。中身は BCM2837 相当で、Raspberry Pi 3 と同じ系統） |
| CPU | Cortex-A53 × 4、1000MHz、AArch64（ARMv8.0-A） |
| メモリ | 512MB（アプリが使えるヒープは約 400MB） |
| 記憶 | microSD カード |
| つなぐ口 | USB（OTG。PC と USB シリアル・USB イーサネットでつながる）、内蔵 Wi-Fi（2.4GHz）、UART（GPIO14・15）、40 ピンのヘッダー |

開発に使うのは Raspberry Pi 5（Raspberry Pi OS 64 ビット）です。PC（Windows など）からも SSH でつなげます。
動作を確かめているのは、実機の Zero 2 W と、QEMU の `raspi3b` だけです。

## 1.5 できること

| 分野 | できること |
|---|---|
| シェル | bash に近い書き方（パイプ、リダイレクト、変数、`if`・`for`・`while`・`case`・関数、`$(...)`、`*` の展開）、行の編集・履歴・Tab の補完 |
| プログラム | C23 の C をその場でコンパイル（`run`）、名前で動かす、`make`・`cc -o`、共有のライブラリ、pthread、OpenMP、curses |
| Linux のソフト | Lua、SQLite、vim、QuickJS、ファイルマネージャー fd、エディタ mi を、ソースのまま動かしています |
| ネットワーク | USB イーサネット、内蔵 Wi-Fi（WPA2、起動時に自動でつなぐ）、DNS、NTP、HTTP・HTTPS（`curl`）、Linux と同じソケット |
| 入り方 | USB シリアル、UART、telnet、SSH（sftp・scp・sshfs も）、HTTP でファイルの読み書き |
| ハードウェア | GPIO、I2C、SPI、ソフトウェアの UART、PWM（ライブラリとコマンド） |
| 守り | 止まったら自動で再起動（ウォッチドッグ）、新しいカーネルは試しに起動してだめなら前のものに戻る（tryboot） |
| 道具 | `top`、`perf`（性能カウンタ）、`dmesg`（記録は SD カードにも残る）、`mem`、`clock` |

## 1.6 できないこと（今のところ）

- `fork`・`exec`、ほかのプログラムとのパイプの同時実行、`&`
- IPv6、ループバック（127.0.0.1）
- C++（コンパイラが C だけ）、`long double` の計算の一部、複素数、アプリで定義する `_Thread_local` の変数
- 共有ライブラリの `dlopen`
- HDMI の画面、USB キーボード、Bluetooth、音

細かい一覧は [第 14 章](14-appendix.md) にあります。

## 1.7 Linux と比べて（得意なこと・苦手なこと）

同じ Zero 2 W で Raspberry Pi OS（Linux）を動かす場合と比べたものです。Monocs の数字は実機で測ったもの、
Linux の側は**測っていない見込み**です（同じ基板で並べて測ったことはまだない）。

### Monocs が得意なこと

| こと | Monocs | Linux（見込み） |
|---|---|---|
| 起動 | カーネルが動き出してから、シェルまで約 1.5 秒（USB）、Wi-Fi で ssh できるまで約 6 秒。この前にファームウェアの起動がある（測っていない） | Zero 2 W では数十秒かかるのがふつう |
| 書いてすぐ動かす | コンパイラが OS の中にあり、メモリ上でつなぐ。小さなプログラムは 0.1 秒前後、2 回目からは 0.01 秒前後 | Zero 2 W の上の gcc は hello.c でも 1 秒前後かかるはず |
| 割り込まれない | アプリがコアを独り占め。ほかのプロセスもスケジューラもない | ふつうのプログラムは、ほかのプロセスや割り込みに数十 µs〜数 ms 止められることがある |
| ハードウェアに近い | GPIO などをシステムコールなしでレジスタから直接読み書き | 1 回ごとにカーネルを通る（`/dev/gpiomem` を使えば直接も可） |

割り込まれないことで、**Linux では特別な設定や仕組みがないと難しいことを、ふつうの C のループで書けます**。

- **ソフトウェアで信号を作る**（ビットバンギング）: WS2812（フルカラー LED のテープ）のように、1 ビットを ±150ns ほどで出す必要があるもの。
- **ソフトウェアで受ける**: Monocs のソフトウェアの UART は、空いたコアで受信のループを回して 115200bps でも取りこぼさない（実機で確かめた）。
- **時間を正確に測る**: 超音波センサー（HC-SR04）のエコー、赤外線リモコンの信号、パルスの幅。
- **すぐに反応する**: GPIO の変化をループで見張れば 1µs 以下で反応できる（Linux の割り込みは数十 µs かかり、ときどき大きく遅れる）。
- **速さを測る**: ほかに何も動いていないので、測るたびの揺れが小さい。

Linux でも、リアルタイムのカーネル（PREEMPT_RT）、コアを空けておく設定（isolcpus など）、カーネルのドライバ、
DMA やハードウェアの機能（pigpio など）を使えばできます。ただし設定と仕組みの知識が要ります。

時間に厳しい処理は、**コア 1・2 で動かす**のがいちばんです（`monocs_core_start`、[第 6 章](06-programs.md) の 6.6）。
コア 0 には 10ms ごとのタイマーと USB・UART・Wi-Fi の割り込みが届きますが、コア 1・2 には仕事の間、止めるとき以外の
割り込みが来ません。ただし、ほかのコアのメモリの読み書きで、キャッシュのミスによる数十〜数百 ns のずれは起こりえます。

### Monocs が苦手なこと

| こと | Monocs | Linux（見込み） |
|---|---|---|
| 重い計算 | slimcc-a64 のコードは GCC より 1.0〜1.3 倍遅い（[第 6 章](06-programs.md) の 6.9） | GCC・clang |
| SD カード | CPU で 1 語ずつ運ぶ（PIO）。まとめて読んで約 22MB/s | DMA を使う |
| Wi-Fi | 同じ LAN の TCP で受ける 3.6〜5MB/s・送る 2.3〜3MB/s（2.4GHz、リンク 65〜72Mbps。電波の側で頭打ち。SDIO 50MHz、CPU で運ぶ PIO） | 電波の速さはほぼ同じなので、大きくは変わらない見込み（測っていない） |
| 同時にいくつも | アプリは 1 つずつ（サービスはコア 3 で裏に動く） | たくさんのプロセス |
| 守り | アプリも OS と同じ特権。悪意のあるプログラムからは守れない | プロセスごとに分ける |
| 使えるソフト | C のソースのまま動くものだけ（C++、fork・exec を使うものは動かない） | パッケージがそろっている |

### まとめ

**「電源を入れて、C を書いて、すぐ動かす」「時間に正確にハードウェアを動かす」ところでは Monocs**、
大きな計算・大量のデータの読み書き・たくさんのソフトを使うことでは Linux、が向いています。

## 1.8 全体の図

```
   PC / Raspberry Pi 5
     │  USB（シリアル・イーサネット）、Wi-Fi（SSH・telnet・HTTP）、UART
     ▼
 ┌─────────────────── Raspberry Pi Zero 2 W ───────────────────┐
 │  コア 0          コア 1・2              コア 3                 │
 │  シェル・アプリ   アプリが借りる         サービス               │
 │                  （コンパイル・pthread） （httpd・sshd・wifid…）│
 │ ───────────────────────────────────────────────────────── │
 │  カーネル: 例外・MMU・メモリ・ロック・VFS（FAT32）・lwIP       │
 │            組み込みのコンパイラ slimcc とリンカ、C ライブラリ   │
 │  ドライバ: UART・USB・SD カード・Wi-Fi・タイマー・割り込み      │
 └──────────────────────────────────────────────────────────┘
     │
   microSD カード（/boot、/usr、/root、/etc …）
```

仕組みの詳しい話は [第 12 章](12-internals.md) にあります。
