# 11. 調べる・困ったとき

## 11.1 様子を見る道具

| コマンド | わかること |
|---|---|
| `dmesg` | カーネルの記録: 起動の表示、サービスの開始・失敗、Wi-Fi・USB のできごと、例外で止まったアプリ、遅かった起動、メモリが足りない |
| `top` | コアごとの忙しさと何が動いているか、メモリ、サービスごとの CPU（q で終わる。`top -b -n 2` は ssh から） |
| `mem` | ヒープ（今といちばん多かったとき）、ファイルのキャッシュ、SD カードの読み書きの回数・時間・誤り |
| `clock` | CPU のクロック（1000MHz か）、温度、電圧、throttled（電圧の低下・熱で遅くなっていないか） |
| `uptime` | 起動からの時間、コア 0 が眠っていた割合 |
| `usb`、`wifi status`、`wifi events` | USB とネットワーク、Wi-Fi の様子 |
| `svc` | 動いているサービス |
| `cache` | コンパイルのキャッシュの量・使えた回数 |
| `time コマンド` | かかった時間 |
| `perf コマンド` | 性能カウンタ（命令の数、キャッシュのミス） |
| `perf record [-e cycles] [-g] コマンド` | どの関数で時間を使っているか |

記録は SD カードにも残ります: `/var/log/dmesg`（今の起動）、`/var/log/dmesg.1`（前の起動）、`/var/log/dmesg.crash`（固まった・止まったときの最後の記録）。
Pi 5 からは `nos.py log`、`curl http://192.168.7.2/.log`。

## 11.2 アプリが落ちた

NULL の参照などで例外が起きると、内容と止まった関数を出してシェルに戻ります。

```
*** exception: Sync / data abort
 ESR 0x0000000096000047  ELR …  FAR 0x0000000000000000
 (NULL pointer)
 at crash_fn+0x8
 from main+0x6c
```

`at` が止まった関数、`from` が呼び出し元です。終了の値は 139。OS もほかのアプリも影響を受けません。

## 11.3 アプリが止まらない

- Ctrl-C、効かなければ Ctrl-\。
- ssh からなら、`ssh` を切るとそのコマンドは止まります。
- 割り込みを止めて回り続けるようなものは止められません。そのときはウォッチドッグ（下）か電源の入れ直し。

## 11.4 OS が固まった・止まった

**ウォッチドッグ**がいつも入っていて、固まると約 16 秒でリセットし、再起動します。カーネルが自分で止まったとき
（直せない例外など）も、表示を記録に残して 5 秒後に再起動します。

再起動した後の `dmesg` に、前の起動の終わり方が出ます。

| 表示 | 意味 |
|---|---|
| `previous boot: ended by reboot` | ふつうの再起動 |
| `… the kernel halted` | カーネルが止まった（止まる直前の行が `/var/log/dmesg.crash` に） |
| `reset without a reboot (a hang and the watchdog?)` | 固まってウォッチドッグがリセットした |
| `no log left in RAM` | 電源が切れていた |

止まったまま調べたい（UART やデバッガで見たい）ときは `watchdog off`。

## 11.5 起動しない

| 様子 | すること |
|---|---|
| 新しいカーネルを Wi-Fi で送った後、つながらない | 2 分ほど待つ。試しの起動に失敗すると、前のカーネルで起動し直す（[第 10 章](10-development.md)） |
| ずっとつながらない | UART をつないで起動の表示を見る（`picocom -b 3000000 /dev/ttyAMA0`） |
| LED が消えたまま・点いたまま | SD カードを PC に差して、`boot/kernel8.img` を前のもの（控え）に戻す。`config.txt` も見る |
| 速い点滅 | SD カードを読めていない。カードを差し直す、別のカードを試す |
| 起動の途中で毎回止まる（あるサービスが悪いなど） | SD カードを PC に差して、`etc/services.txt` のその行を `#` にする |

UART だけ生きているときは、電源を入れた直後にシェルの組み込みのコマンドを送れます。たとえば、壊れたサービスを外すには
`recv /etc/services.txt …`（nos.py の `--uart push`）で一覧を置き換えてから `reboot`。

## 11.6 つながらない

| 症状 | 見るところ |
|---|---|
| Wi-Fi の ssh がつながらない | `wifi status`（USB・UART から）。アドレスが変わっていないか。`/etc/wpa_supplicant.conf` |
| Wi-Fi から断られる | パスワード（`passwd`）か鍵（`/root/.ssh/authorized_keys`）。まちがいが続いて 30 秒断っているかも |
| 「console is in use」 | 対話のシェルはすでにほかでつながっている（1 つまで） |
| ssh のコマンドが返ってこない | コンソールでアプリが動いている（「waiting for …」の知らせ）。そのアプリを終える |
| USB シリアルが黙った | `nos.py --uart reboot`。USB を抜き差し |
| HTTPS がつながらない | 時刻が合っているか（`date` に「推定」と出ていないか） |

## 11.7 遅い

- `clock` で 1000MHz か（`config.txt` の `force_turbo=1`）、throttled が 0 か。
- 初めて動かすものはコンパイルの分だけかかります（0.5 秒を超えると「compiling 12/38 files」と進み具合を出します）。
- 遅い起動は `dmesg` に「slow start」と内訳が残ります（基準は環境変数 `MONOCS_SLOW_MS`、既定 1000ms）。
- SD カードの書き込みは、同じ量でもカードの中の状態で 2〜3 倍揺れます。

## 11.8 コンパイルのキャッシュがおかしい

ソースを直したのに古い動きのままに見えるとき（時計を戻して同じ大きさで書き換えたときなど、まれに見逃すことがあります）:

```sh
cache clear 名前          # そのプログラムの分だけ消す（例: cache clear vim）
cache clear              # 全部
```

## 11.9 SD カードが壊れた

1. まず区画をまるごと取り出して控えます: `curl -o fat.img http://192.168.7.2/.sdcard/fat.img`（Wi-Fi なら `--digest -u monocs`）。
2. Pi 5 で `fsck.vfat -n fat.img` で調べます（`-n` は直さない）。
3. 直したイメージは `curl -T fat.img http://192.168.7.2/.sdcard/fat.img` で書き戻せます（区画と同じ大きさのときだけ。書いたら再起動する）。

SD カードを PC に差して `fsck.vfat` をかけてもかまいません。控え（`build/sd-backup/`）は残しておきます。
